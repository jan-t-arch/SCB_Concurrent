系統規則 — 開發參考System Rules — Development Reference

本表只記錄已確認的系統業務規則、觸發點及預期行為。未確認項目不會列作規則；英文內容為標準，中文內容與英文保持一致。 This table records confirmed system business rules, triggers and expected behaviour only. Unresolved items are not treated as rules. English is the governing version and the Chinese content follows it.
適用範圍：Concurrent Submission、PDF、簽署及提交生命週期Scope: Concurrent Submission, PDF, signing and submission lifecycle

Rule ID 觸發條件／範圍Trigger / Condition 預期系統行為Expected System Behaviour
SYS-01共享資料範圍Shared data scope 多份 Application屬於同一 Concurrent Group。Multiple applications belong to the same Concurrent Group.
  • Concurrent Submission答案必須由同一組內所有相關 Application共用。Concurrent Submission answers must be shared by all related applications in the group.
  • 共享資料包括 declaration option、Policy Selection、AC11、AC7.2及 Manual Policy。Shared data includes the declaration option, Policy Selection, AC11, AC7.2 and Manual Policies.
  • 任何相關 Application開啟 Concurrent Submission時，必須讀取同一份共享內容。Every related application must read the same shared content when Concurrent Submission is opened.
SYS-02Application狀態隔離Application state isolation 用戶切換或操作不同 Application。The user switches between or acts on different applications.
  • Section completion、PDF generation、signing、submission及 submission-success blocker必須按 Application獨立保存。Section completion, PDF generation, signing, submission and the submission-success blocker must be stored independently per application.
  • 切換 Application不得複製、清除或繼承另一份 Application的狀態。Switching applications must not copy, clear or inherit another application's state.
SYS-03資料保留及完成判斷Retention and completion 用戶切換 Option、編輯內容、按 OK或 Next Page。The user switches options, edits content, presses OK or presses Next Page.
  • 在 Option A及 Option B之間切換時，已輸入的共享答案必須保留。Shared answers must be retained when switching between Option A and Option B.
  • 隱藏或目前不適用的欄位不可參與當前 validation。Hidden or currently inapplicable fields must not participate in the current validation.
  • Completion必須根據目前有效內容判斷，包括仍在 Edit Mode內的內容。Completion must be derived from the current valid content, including content still in Edit Mode.
  • OK只退出 Edit Mode；Next Page只負責導航，兩者均不是 Save或 completion gate。OK only exits Edit Mode and Next Page only navigates; neither is a Save or completion gate.
SYS-04Policy Selection validationPolicy Selection validation Option B或部分選取 Policy。Option B is selected or the policy selection is partial.
  • Option B的 Selected Policy List不可為空；空白時顯示 inline red validation並阻止 Generate PDF。The Option B Selected Policy List must not be empty; an empty list shows inline red validation and blocks Generate PDF.
  • Current Application的 Policy Card不屬強制選取項目；任何符合資格的 Policy Card均可滿足非空要求。The Current Application's Policy Card is not mandatory; any eligible Policy Card may satisfy the non-empty requirement.
  • 部分選取時，AC11及 AC7.2是兩個獨立控件，兩項均須符合各自的 mandatory rule。For partial selection, AC11 and AC7.2 are separate controls and each must satisfy its own mandatory rule.
SYS-05Policy List RefreshPolicy List Refresh 進入 Concurrent Submission、提出 Generate PDF要求或按 Start Signing。Concurrent Submission is entered, Generate PDF is requested or Start Signing is pressed.
  • 系統必須讀取最新 Policy List及 Policy lifecycle status。The system must read the latest Policy List and Policy lifecycle status.
  • 需要偵測新增／刪除 Policy、status改變及 Premium、Pay Term、Type、Frequency、pt等重要資料改變。The system must detect added or removed policies, status changes and material changes to Premium, Pay Term, Type, Frequency or pt.
  • Manual Policy新增、刪除或重要資料修改亦屬 Policy List更新。Adding, removing or materially changing a Manual Policy is also a Policy List update.
SYS-06無 Outstanding PDF的資料變更Change without outstanding PDF 沒有 Generated-but-unsubmitted／unvoided PDF，而進入 Concurrent Submission或 Generate PDF前發現 Policy List已改變。No generated-but-unsubmitted or unvoided PDF exists, and a Policy List change is found when Concurrent Submission is entered or before Generate PDF.
  • Concurrent section必須顯示 Warning；任何 section有 Warning時均不可產生新 PDF。The Concurrent section must show Warning; no new PDF may be generated while any section shows Warning.
  • 如果更新是在 Generate PDF checkpoint發現，本次 Generate PDF必須停止，並要求用戶先進入 Concurrent Submission覆核最新資料。If the change is found at the Generate PDF checkpoint, that attempt must stop and the user must first enter Concurrent Submission to review the latest data.
  • 只進入、離開或再次進入 Concurrent Submission，以及按 OK、Save或 Next Page，均不可自動清除 Policy change Warning。Entering, leaving or re-entering Concurrent Submission, and pressing OK, Save or Next Page, must not automatically clear the Policy change Warning.
  • 用戶須進入 Edit Mode覆核最新內容；Form在 Edit Mode內通過正常 declaration validation時，Warning即時清除並恢復 Completed，不需要按 OK儲存。The user must review the latest content in Edit Mode; when the form passes normal declaration validation inside Edit Mode, Warning clears immediately and Completed is restored without requiring OK to save.
  • 如 Form仍然 Fail，Warning必須保留，直至所有適用 validation均通過。If the form still fails, Warning must remain until all applicable validations pass.
SYS-07Outstanding PDF鎖定Outstanding PDF lock 任何相關 Application已有 Generated PDF，且尚未 Submit或 Void。Any related application has a Generated PDF that has not been submitted or voided.
  • 整個共享 Concurrent Submission不可進入 Edit Mode，但仍須顯示最新 Policy List及最新 Policy Status。The shared Concurrent Submission must not enter Edit Mode, but it must still display the latest Policy List and Policy Status.
  • Policy Card不設獨立 read-only規則；不能修改由整體 shared-form lock控制。A Policy Card has no independent read-only rule; non-editability is controlled by the shared-form lock.
  • Policy List更新不產生額外 change warning。Policy List updates do not create an additional change warning while locked.
  • 其他符合自身 section requirements及共享 declaration gate的 Application仍可產生自己的 PDF，不需要等待較早 Application Submit或 Void。Another application that meets its own section requirements and the shared declaration gate may generate its own PDF without waiting for the earlier application to be submitted or voided.
  • 擁有 active PDF的 Application被重新開啟時，系統必須返回該 Application自己的 Preview & Sign Page，而不是顯示 Concurrent Submission。When an application that owns an active PDF is reopened, the system must return to that application's own Preview & Sign Page rather than display Concurrent Submission.
  • 沒有 active PDF的相關 Application才顯示 locked、read-only的最新 Concurrent Submission。例如 App A有 active PDF時，App B／C可查看 locked Concurrent；如 App A及 App B均有 active PDF，則由尚未產生 PDF的 App C查看。Only a related application without its own active PDF displays the latest locked, read-only Concurrent Submission. For example, if App A has an active PDF, App B or C may view locked Concurrent; if App A and App B both have active PDFs, an App C without a PDF is used to view it.
SYS-08PDF SnapshotPDF Snapshot 為某份 Application產生 PDF。A PDF is generated for an application.
  • 每份 Application的 PDF及 signing lifecycle必須獨立。Each application's PDF and signing lifecycle must remain independent.
  • PDF必須保存產生當刻所使用的 application data snapshot。The PDF must retain the application data snapshot used at generation time.
  • 其他 Application的後續操作不可修改已產生 PDF的內容或 signing status。Subsequent actions in another application must not modify the generated PDF content or signing status.
SYS-09Max／Total計算觸發點Max / Total calculation triggers Policy資料、背景 calculation inputs或選取內容改變。Policy data, background calculation inputs or selected content changes.
  • Max及 Total Premium不可因一般輸入或 Policy List變動而即時重新計算。Max and Total Premium must not recalculate in real time merely because input or the Policy List changes.
  • 只在進入 Concurrent Submission及按 Start Signing時重新計算。Recalculation occurs only when Concurrent Submission is entered and when Start Signing is pressed.
  • Generate PDF會讀取最新 Policy List，但不重新計算 Max／Total。Generate PDF reads the latest Policy List but does not recalculate Max or Total.
SYS-10Max EnforcementMax Enforcement 系統取得最新 Total及 Maximum結果。The system obtains the latest Total and Maximum result.
  • 判斷採用 strict <；只有 Total < Maximum才 Pass。The comparison uses strict <; only Total < Maximum passes.
  • Total = Maximum或 Total > Maximum均為 Fail。Total = Maximum and Total > Maximum both fail.
  • Concurrent Submission顯示 Over Max時，只顯示結果及提示，不可令 section incomplete或阻止 Generate PDF。An Over Max result shown in Concurrent Submission is informational; it must not make the section incomplete or block Generate PDF.
  • 真正的 Over Max blocking只在 Start Signing發生。Actual Over Max blocking occurs only at Start Signing.
SYS-11Start Signing validationStart Signing validation 用戶在 Sign Page按 Start Signing。The user presses Start Signing on the Sign Page.
  • 系統讀取最新 Policy List並重新計算最新 Max及 Total。The system reads the latest Policy List and recalculates the latest Max and Total.
  • Pass時允許開始簽署；Fail時阻止簽署但保留已產生 PDF。A Pass allows signing to start; a Fail blocks signing but retains the generated PDF.
  • Fail後用戶可返回 PDF Preview或 Void PDF後覆核資料。After a Fail, the user may return to PDF Preview or void the PDF and review the data.
  • 一份 Application的 Start Signing結果不可影響其他 Application。One application's Start Signing result must not affect another application.
SYS-12Manual PolicyManual Policy 用戶手動新增或修改未顯示於 detected list的 Policy。The user manually adds or changes a policy not shown in the detected list.
  • Manual Policy必須具有有效 Type及 Premium；未填妥時 Concurrent validation Fail。A Manual Policy must have a valid Type and Premium; an incomplete policy fails Concurrent validation.
  • Regular Manual Policy固定使用 Monthly Frequency，UI不提供 Frequency dropdown。A Regular Manual Policy always uses Monthly Frequency and the UI does not provide a Frequency dropdown.
  • Regular使用 Monthly Premium及 pt參與計算；Single使用 Single Premium。Regular uses Monthly Premium and pt in the calculation; Single uses Single Premium.
  • Manual Policy修改只在下一個 calculation checkpoint反映到 Max／Total。Manual Policy changes affect Max and Total only at the next calculation checkpoint.
SYS-13Submit及 Void生命週期Submit and Void lifecycle Application被 Submit、PDF被 Void或提交記錄被作廢。An application is submitted, a PDF is voided or a submission record is voided.
  • 每份 Application必須獨立 Submit；Submit不可自動改變其他 Application狀態。Each application must submit independently; submission must not automatically change another application's state.
  • Void PDF只清除目標 Application的 PDF及 signing狀態。Void PDF clears only the target application's PDF and signing state.
  • 只有所有 Outstanding PDF均已 Submit或 Void，共享 Concurrent Submission才解除 Edit Lock。The shared Concurrent Submission unlocks for editing only after every Outstanding PDF has been submitted or voided.
  • Application提交成功後不可繼續一般編輯或簽署；切換離開再返回時 Submitted狀態必須保留。After successful submission, normal editing and signing are unavailable, and the Submitted state must persist after switching away and back.
SYS-14Status UI一致性Status UI consistency Section completion、validation、Policy change或 PDF lifecycle status改變。Section completion, validation, Policy change or PDF lifecycle status changes.
  • Completed及 Warning必須互斥，任何 section同一時間只顯示其中一個。Completed and Warning must be mutually exclusive; a section shows only one at a time.
  • Policy change warning與一般 validation warning由不同原因控制，但 UI只呈現目前有效狀態。Policy change and normal validation warnings are driven by different causes, but the UI presents only the currently effective state.
  • PDF lifecycle status、section completion及 validation status不可混作同一個狀態。PDF lifecycle status, section completion and validation status must not be treated as the same state.
  • 任何 section顯示 Warning時，Generate PDF必須 disabled；全部適用 section均為 Completed時才可產生新 PDF。Generate PDF must be disabled while any section shows Warning; a new PDF may be generated only when every applicable section is Completed.
  • 重新開啟該 Application已存在的 PDF不屬於產生新 PDF，因此不受上述 Generate PDF gate限制。Reopening an existing PDF for that application is not generation of a new PDF and is therefore not blocked by the above Generate PDF gate.
