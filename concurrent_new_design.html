此原型的未定問題Open questions in this prototype

以下項目仍需 BA／AC 確認。The following points still require BA/AC confirmation.

  1. AC11與AC14第8項的mandatory條件互相矛盾。
    AC11「Generic Reason for Concurrent Assessment」寫明：只有在用戶只選取部分Policy時，Generic Reason才是必填。換言之，如Situation 3內所有Policy均已選取，按AC11本身便不應要求此原因。
    但AC14第8項及mockup要求：Situation 3即使所有Policy均已選取，AC11仍須顯示並為必填。
    目前Demo採用：按AC14第8項及mockup處理；Situation 3一律要求完成AC11。
    待確認：正式系統應只在部分選取時要求AC11，還是在Situation 3任何選取組合下均要求AC11。     AC11 and AC14 item 8 define conflicting mandatory conditions.
    AC11, “Generic Reason for Concurrent Assessment”, states that the Generic Reason is mandatory only when the user selects some, but not all, Policies. Under AC11 alone, the reason should therefore not be required when all Policies in Situation 3 are selected.
    However, AC14 item 8 and the mockup require AC11 to remain visible and mandatory in Situation 3 even when all Policies are selected.
    Current Demo decision: Follow AC14 item 8 and the mockup; AC11 is mandatory for every Situation 3 selection combination.
    Confirmation required: Should production require AC11 only for partial selection, or for every selection combination in Situation 3?
  2. 未定：如已產生PDF後、完成簽署／提交前，PDF內唯一被選取的Policy被其他Application刪除，正式系統應容許繼續使用舊PDF，還是要求作廢並按最新Concurrent資料重新產生？目前Demo容許繼續簽署及提交已凍結PDF。Open: If the only selected policy in a generated PDF is deleted by another application before signing or submission is completed, should production allow the frozen PDF to continue, or require invalidation and regeneration from the latest Concurrent data? The current demo allows the existing frozen PDF to be signed and submitted.

SYS-01共享資料範圍Shared data scope 多份 Application屬於同一 Concurrent Group。Multiple applications belong to the same Concurrent Group.
  • Concurrent Submission答案必須由同一組內所有相關 Application共用。Concurrent Submission answers must be shared by all related applications in the group.
  • 共享資料包括 declaration option、Policy Selection、AC11、AC7.2及 Manual Policy。Shared data includes the declaration option, Policy Selection, AC11, AC7.2 and Manual Policies.
  • 只有按OK後的整份Concurrent Draft才成為共享已保存內容；Saved Incomplete Manual Policy亦跨App顯示，但不屬有效Policy List。Only the whole Concurrent Draft committed by OK becomes saved shared content. A Saved Incomplete Manual Policy is also visible across Apps but is not part of the effective Policy List.
  • 任何相關 Application開啟 Concurrent Submission時，必須讀取同一份共享內容。Every related application must read the same shared content when Concurrent Submission is opened.
  • Policy List變更確認亦屬Group-level行為；任一相關Application在Edit Mode內按有效的OK，可確認同一份已覆核清單並清除整個Group的同類「<!>」。Policy List change acknowledgement is also Group-level. A valid OK in Edit Mode from any related Application acknowledges the same reviewed list and clears that type of “<!>” for the whole Group.
SYS-02Application狀態隔離Application state isolation 用戶切換或操作不同 Application。The user switches between or acts on different applications.
  • Section completion、PDF generation、signing、submission及 submission-success blocker必須按 Application獨立保存。Section completion, PDF generation, signing, submission and the submission-success blocker must be stored independently per application.
  • 切換 Application不得複製、清除或繼承另一份 Application的狀態。Switching applications must not copy, clear or inherit another application's state.
  • Add Application只建立空白App及更新Control Panel的App List，不可自動切換目前App或改變目前畫面。只有用戶按目標App按鈕才切換；一般目標App須開啟Concurrent Submission Preview／read-only mode，不可自動進入Edit Mode。已有PDF或已Submitted App仍按其獨立lifecycle畫面返回。Add Application only creates the empty App and updates the Control Panel App List; it must not switch the current App or change the current screen. Switching occurs only when the user presses the target App button. A normal target App opens Concurrent Submission in Preview/read-only mode and must not enter Edit Mode automatically. An App with an existing PDF or a submitted App still returns according to its independent lifecycle screen.
  • Delete Policy只移除Owner App的Quotation Policy，App本身必須保留；Delete App則連同其Policy、PDF及signing progress一併刪除。Delete Policy removes only the owner App's Quotation Policy and keeps the App; Delete App cascades to its Policy, PDF and signing progress.
SYS-03資料保留及完成判斷Retention and completion 用戶切換 Option、編輯內容、按 OK或 Next Page。The user switches options, edits content, presses OK or presses Next Page.
  • 除同一Concurrent Group首次把User Declaration改為Yes／Option B時執行一次預設Select All外，在Option A及Option B之間切換必須保留已輸入的共享答案及Policy selections。Except for the one-time default Select All when User Declaration is first changed to Yes/Option B within the Concurrent Group, switching between Option A and Option B must retain the shared answers and Policy selections.
  • 隱藏或目前不適用的欄位不可參與當前 validation。Hidden or currently inapplicable fields must not participate in the current validation.
  • 進入Edit Mode時，系統必須以最後已儲存的共享內容建立獨立Draft；編輯每個答案只修改Draft，不可逐項自動儲存。Entering Edit Mode must create an isolated Draft from the last saved shared content. Editing individual answers changes the Draft only and must not auto-save field by field.
  • OK是整份Concurrent Draft的Save action：一次過儲存declaration、selection、AC11、AC7.2及Manual Policies，即使內容未完整亦可保存。Back必須放棄整份未保存Draft並還原進入Edit Mode前的內容。OK is the Save action for the entire Concurrent Draft: it atomically saves the declaration, selections, AC11, AC7.2 and Manual Policies, even if the content is incomplete. Back must discard the whole unsaved Draft and restore the content from before Edit Mode.
  • Completion必須根據最後已儲存的適用內容判斷；Edit Mode內可顯示Draft的即時validation作提示，但未按OK的Draft不可成為其他Application讀取的正式狀態。Completion must be derived from the last saved applicable content. Draft validation may be shown live within Edit Mode, but an uncommitted Draft must not become the official state read by another Application.
  • Next Page只負責導航，不會保存Draft、確認Policy List變更或清除Warning。Next Page only navigates; it does not save the Draft, acknowledge a Policy List change or clear a Warning.
SYS-04Policy Selection validationPolicy Selection validation 用戶選擇Option A或Option B；系統偵測多張Policy，或用戶只選取部分Policy。The user selects Option A or Option B; multiple Policies are detected, or the user selects only part of the Policy List.
  • Option A必須保留原文「No further concurrent application/this is not last application of concurrent submission of client」。系統把它解讀為：目前Application在本次獨立簽署，其他Application稍後處理，因此本次視為No Concurrent Submission。Option A must retain the wording “No further concurrent application/this is not last application of concurrent submission of client”. The system interprets it as signing the current Application alone in this signing batch while other Applications are handled later; this batch is treated as No Concurrent Submission.
  • Option A只把目前App Policy納入Total、Max及PDF；如系統偵測其他Policy（包括Complete Manual Policy），AC7.2 Reasons for de-select the transaction為必填。Complete Manual Policy只證明另有同日Policy，不會因Option A而被納入本次簽署。Option A includes only the current App Policy in Total, Max and PDF. If other Policies are detected, including a Complete Manual Policy, AC7.2 Reasons for de-select the transaction is mandatory. A Complete Manual Policy establishes that another same-day Policy exists but is not included in the current signing batch under Option A.
  • Option B的有效Included Policy List不可為空；至少一張已選取的auto-searched Policy或一張已完成並按OK保存的Manual Policy方可滿足。空白時顯示inline red validation並阻止產生新PDF。The effective Included Policy List for Option B must not be empty. At least one selected auto-searched Policy or one complete, OK-saved Manual Policy is required. An empty list shows inline red validation and blocks creation of a new PDF.
  • 同一Concurrent Group首次把User Declaration改為Yes／Option B時，系統必須預設選取當刻Policy List內所有auto-searched Policies；Manual Policy不屬此預設選取範圍。When User Declaration is first changed to Yes/Option B within a Concurrent Group, every auto-searched Policy in the Policy List at that moment must be selected by default; Manual Policies are outside this default selection.
  • 其後由Yes／Option B改為No／Option A再改回Yes／Option B時，不可再次執行Select All，原有Policy selections必須保持不變。首次Yes後才新搜尋到的Policy亦保持未選取，直至用戶明確選取。If the declaration is subsequently changed from Yes/Option B to No/Option A and back to Yes/Option B, Select All must not run again and the previous Policy selections must remain unchanged. A Policy first detected after the initial Yes also remains unselected until the user explicitly selects it.
  • 首次Yes狀態及Policy selections屬Concurrent Group共享資料；切換Application不可把另一Application當作新的首次Yes。重新載入已保存的Yes答案亦不可重新執行預設選取。The first-Yes state and Policy selections are shared at Concurrent Group level; switching Applications must not treat another Application as a new first Yes. Reloading an already-saved Yes answer must not run the default selection again.
  • Current Application的 Policy Card不屬強制選取項目；任何符合資格的 Policy Card均可滿足非空要求。The Current Application's Policy Card is not mandatory; any eligible Policy Card may satisfy the non-empty requirement.
  • 「Current Policy不必被選取」只適用於Option B的selection；Current Application本身仍須在Quotation保留有效Policy，並在Start Signing重新確認其存在。“The Current Policy need not be selected” applies only to Option B selection. The Current Application must still retain a valid Policy in Quotation, whose existence is rechecked at Start Signing.
  • AC11及 AC7.2是兩組獨立問題；當兩組同時適用時，兩組均必須分別完成。AC11 and AC7.2 are independent question groups; when both apply, both groups must be completed separately.
  • AC11及AC7.2均使用checkbox並允許多選；問題適用時，每組至少須選取一項。選取或取消其中一項不可自動清除同組其他已選答案。AC11 and AC7.2 use checkboxes and allow multiple selections. When a question applies, at least one answer is required in each group. Selecting or clearing one answer must not automatically clear another selected answer in the same group.
  • AC11選擇「其他原因」時，說明文字為必填；取消「其他原因」後可保留已輸入文字，但該文字不可參與目前validation、計算或PDF內容。PDF須顯示所有已選取的AC11及AC7.2答案。When AC11 “Other reasons” is selected, the explanatory text is mandatory. After “Other reasons” is cleared, the entered text may be retained but must not participate in current validation, calculation or PDF content. The PDF must display every selected AC11 and AC7.2 answer.
  • Policy被刪除並於 refresh checkpoint從最新清單移除時，其 shared selection tick亦須清除；不可讓已刪除 Policy繼續參與 gate或計算。When a deleted policy is removed from the latest list at a refresh checkpoint, its shared selection tick must also be cleared; a deleted policy must not continue to participate in the gate or calculation.
SYS-05Policy List RefreshPolicy List Refresh 進入Concurrent Submission或按Start Signing。Concurrent Submission is entered or Start Signing is pressed.
  • 無論是否有Outstanding PDF，系統均須在兩個checkpoint重新搜尋最新Policy List及Policy lifecycle status。沒有Outstanding PDF時，搜尋結果可更新顯示清單；有Outstanding PDF時，只在後台識別Pending差異，不可更新已凍結Group清單或任何已產生PDF。At both checkpoints, the system must re-search the latest Policy List and lifecycle status whether or not an outstanding PDF exists. Without an outstanding PDF, the displayed list may be updated; with an outstanding PDF, differences are identified only as Pending in the backend and must not update the frozen Group list or any generated PDF.
  • 需要偵測新增／刪除 Policy、同時新增及刪除、Quotation ID不同、status改變，以及Premium、Pay Term、Type、Frequency、pt等重要資料改變。The system must detect added policies, removed policies, simultaneous additions and removals, a changed Quotation ID, status changes, and material changes to Premium, Pay Term, Type, Frequency or pt.
  • Manual Policy只在按OK後比較「有效清單」變更：Incomplete→Complete視為Add、Complete重要資料修改視為Update、Complete→Incomplete或Delete Complete視為Remove；新增／修改／刪除Incomplete Manual Policy均不構成Policy List Change。Manual Policy changes are compared against the effective list only after OK: Incomplete→Complete is Add, a material change to a Complete row is Update, and Complete→Incomplete or deleting a Complete row is Remove. Adding, changing or deleting an Incomplete Manual Policy is not a Policy List Change.
  • 每次顯示Policy List時，如目前Application是該清單的Group成員，其自己的Policy必須排列在最上方；其他Policy維持原有搜尋次序。鎖定後新增而尚未加入Group的Current App／Policy不可在凍結清單顯示；解鎖並加入後才排首位。此排序只影響顯示，不可改變selection、validation或計算。Whenever the Policy List is displayed, the current Application's own Policy must appear at the top if it is a member of that list. A Current App/Policy added after lock and not yet admitted to the Group must not appear in the frozen list; once admitted after unlock, it appears first. This ordering affects display only and must not change selection, validation or calculation.
  • Preview & Sign只進入Submit Page，不屬Policy List refresh或Max／Total recalculation checkpoint。Preview & Sign only opens the Submit Page and is not a Policy List refresh or Max/Total recalculation checkpoint.
SYS-06無 Outstanding PDF的資料變更Change without outstanding PDF 沒有Outstanding PDF，而在進入Concurrent Submission或按Start Signing時發現Policy List已改變。No outstanding PDF exists, and a Policy List change is found when Concurrent Submission is entered or Start Signing is pressed.
  • Concurrent Group內所有未提交Application的Concurrent section必須顯示同一個Group-level Warning；任何適用section有Warning時，該Application均不可產生新PDF。The Concurrent section of every unsubmitted Application in the Concurrent Group must show the same Group-level Warning; an Application cannot generate a new PDF while any applicable section shows Warning.
